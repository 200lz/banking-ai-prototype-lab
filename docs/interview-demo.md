## What failed and what I learned

| Failure or boundary | Response and lesson |
| --- | --- |
| Initial local evaluation defects | Missing information and DTI inputs did not always trigger review, routing missed synonyms, and a retrieved SYSTEM spoof passed through. Preserved the failing baseline, corrected general controller rules and added independent scorer/mutation checks. Evaluation belongs before a success claim. |
| Docker portability and response shape | The container web proxy stripped calculation provenance. Docker 20 also changed an ephemeral port after restart while the verifier retained the old address. Added schema regression coverage and rediscovered the actual loopback binding. Healthy services and a failing probe require separate diagnoses. |
| Databricks Workspace Files Errno 5 | Runtime reads failed before RAW/schema writes despite verified paths, file types and permissions. Preserved both failed runs and stopped retrying the unchanged artifact. Provider cause remains unresolved; an unsupported Free Edition feature was not established. |
| Wheel and Unity Catalog Volume boundary | Packaged the same financial logic and exact RAW bytes into a small wheel, verified upload/download hashes, then ran a package smoke before the pipeline. The migrated job passed once and real SQL verified exact outputs. Make executable artifacts and data provenance explicit. |
| AWS Lambda quota confusion | A submitted request did not establish applied capacity, and regional limits differed. Fresh Tokyo settings confirmed 1000, enabling reservation three and leaving 997 unreserved. Verify actual regional settings before changing deployment constraints. No new request for 1001 was made. |
| Bedrock zero capacity / throttling | Discovery and access metadata passed, but inference qualification failed and relevant account quotas were zero. Stopped model retries, kept failed usage incomplete and separated infrastructure proof from live-model quality. |
| Preserving safety boundaries | Kept scoped runtime IAM, required MFA, legitimate OAuth, Tokyo-only deployment, reservation three and mandatory review. The nine-check infrastructure-only run passed with zero model usage. Delayed CloudWatch delivery required a bounded verifier correction; authentication and correlation requirements stayed intact. |
